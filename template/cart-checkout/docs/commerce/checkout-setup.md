# Cart and PayPal checkout setup

Author and publish five EDS pages using one block each: `cart` and `cart-summary` on the cart route, `checkout` on checkout, `order-review` on review, `order-complete` on complete, `order-cancel` on cancel. Set routes in `scripts/commerce/checkout-config.js` to the actual same-site published paths. An EDS block is a one-cell table titled with the block name. Link your existing PDP to `addProductToCart`; `cart-summary` contains the PayPal Express action. Optionally load `styles/commerce-tokens.css` from your site's global stylesheet, or override its `--commerce-*` properties using site design tokens; block CSS includes fallbacks.

Set the **explicit API origin**, org, site, country, and **public** PayPal client ID in `checkout-config.js`. Keep `paypal.environment: "sandbox"` until your own sandbox testing is complete. Configure the Commerce API PayPal secret server-side with `orderReview.checkout` and `orderReview.express` enabled and published HTTPS success/cancel/review URLs. No PayPal client secret belongs in site code or CLI input. The Commerce API must be reachable with the storefront's CORS settings, and the merchant must supply allowed shipping methods for its country. The default form asks for a region and postal code; adapt its address fields and validate shipping/tax/payment in the merchant's country before enabling a locale beyond the unit-test fixture. Guest preview/create may require a site-provided `window.edgeCommerceRecaptchaToken(action)` function that returns a browser reCAPTCHA token; if enforced by your API configuration, connect this before enabling checkout. The CLI does not provision provider settings or publish pages.

Standard checkout gathers guest email and shipping, estimates shipping, previews totals, creates an order with its estimate token, and redirects to PayPal; the Commerce API returns to review after approval. Cart PayPal Express uses SDK v6 and the Commerce API's PayPal session endpoints; shipping changes always preview a matching order before approval. Review calls confirm/cancel, reuses a confirmation idempotency key, and checks the fetched API order state. Completion shows thanks only for `payment_completed` and clears the cart only then. Sandbox-test *both* payment journeys, initial and changed shipping methods, pending/failed confirmation, and return URLs before production. PayPal v6 public setup documentation has inconsistent client-token examples; this starter uses its recommended public client ID for one-time PayPal payments pending sandbox verification.

Do not install this alongside another block with the same name without a manual integration pass. `edge-commerce check` compares installed files to the manifest; locally edited config will be reported, not overwritten.
